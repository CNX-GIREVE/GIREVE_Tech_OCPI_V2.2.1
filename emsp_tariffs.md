# `Tariffs Module Specifications`

IOP follows the OCPI standard for Tariffs upload by a CPO. [See OCPI specifications.](https://github.com/ocpi/ocpi/blob/release-2.1.1-bugfixes/mod_tariffs.md)

## PULL Tariffs ToIOP: Object ID

The id field of the Tariff object is mapped with the id provided by the CPO platform.

## PULL Tariffs ToIOP: “gireve_id” An Extra Gireve Property

Gireve will introduce a new field (not part of the OCPI protocol) called gireve_id. This is a unique ID generated by Gireve for each tariff.

## PULL Tariffs ToIOP: Tariff Type

Gireve stores all tariffs coming from CPOs, whatever their nature, but transfers only “B2B Regular” tariffs to eMSPs.

## PULL Tariffs ToIOP: CPO Targeting

If an eMSP wants to retrieve **all the tariffs of the CPOs** with which it has a roaming contract, it must use the **IOP**’s **country_code** and **party_id** in the headers **ocpi_to_country_code** and **ocpi_to_party_id**.

If the eMSP wants to retrieve the tariffs of a **specific CPO** with which it has a roaming contract, it must use the **CPO**’s **country_code** and **party_id** in the headers **ocpi_to_country_code** and **ocpi_to_party_id**.

## PULL Tariffs ToIOP: eMSP Targeting

Gireve has introduced the ability for a CPO to target a specific eMSP when sending a tariff by adding two fields :
-  target_operator_country_code
-  target_operator_party_id

[see Differentiate tariff per eMSP](cpo_tariffs.md)

Hence, eMSPs connected via OCPI 2.2.1 will receive, when pulling tariffs, the descriptions of the full list of valid tariffs from CPO(s), whether or not these tariffs are specific to the requesting eMSP. 

**Tariffs specific** to an **eMSP** will have the fields **target_operator_country_code** and **target_operator_party_id** filled in.

## PULL Tariffs ToIOP: Get List Pagination

If the eMSP wants to retrieve a list of tariffs, it can call the URL: /ocpi/sender/2.2.1/tariff?date_from= using the paginated properties date_from, date_to, offset and limit.

Parameters « offset » and « limit » are optional but IOP always returns a paginated response (subset of objects list and link, X-Total-Count and X-limit headers).
The eMSP must call the link returned in the headers to get the next pages. 

IOP has its own max limit (**100 Tariffs**) and answers with its if the client limit is upper than IOP one or the client doesn’t set its limit.

The timeframe (‘date_from’ and ‘date_to’) used in the request parameters must be lower than one month.

## Specific properties added by Gireve

**TariffDimensionType “SESSION_TIME”**
In standard OCPI V2.2.1, the CPO can define 2 different “TariffDimensionType” related to the duration :

-  TIME: “time charging: defined in hours, step_size multiplier: 1 second” 
(description from the OCPI Github).
-  PARKING_TIME: “time not charging: defined in hours, step_size multiplier: 1 second” 
(description from the OCPI Github).

Gireve adds a third “TariffDimensionType” named “SESSION_TIME” with the following description:
-  SESSION_TIME: “time charging or not: defined in hours, step_size multiplier: 1 second”.

### Information and Requirements

-  The “id” field of the tariff object is mapped to the identifier provided by the CPO.
-  Gireve include a new field, gireve_id, which is not part of the OCPI protocol. This field will be a unique identifier generated by Gireve for each tariff.
-  Gireve stores all tariffs coming from CPOs, whatever their nature, but transfers only “B2B Regular” tariffs to eMSPs.
-  By filling the 2 headers “ocpi-to-country-code” and “ocpi-to-party-id” by the CPO’s country_code and party_id, the eMSP is able to retrieve only the tariffs of this specific CPO.
-  Tariffs specific to an eMSP will have the fields “target_operator_country_code” and “target_operator_party_id” filled in
-  eMSPs can now receive a new TariffDimensionType called SESSION_TIME (charging time + parking time).
